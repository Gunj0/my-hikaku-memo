# システム設計

## 1. 文書の目的

本書は、「オレの比較メモ」のシステム構成、技術選定、責務分担、および画面全体の実装方針を整理する。

## 2. システム概要

本システムは、ホーム、保存済みメモ一覧、比較編集、メモ閲覧の各ページで構成される Web アプリケーションである。
比較編集体験は /memos/new 上の単一画面で完結し、画面内ステップの切り替えで進行する。

## 3. 技術スタック

| 項目           | 採用技術                  | 用途                                  |
| -------------- | ------------------------- | ------------------------------------- |
| フレームワーク | Next.js 16                | App Router によるアプリケーション構成 |
| UI ライブラリ  | React 19                  | 画面描画と状態更新                    |
| 認証           | Auth.js + Google Provider | Google ログインとセッション管理       |
| 言語           | TypeScript                | 型安全な実装                          |
| スタイリング   | Tailwind CSS 4 系         | レイアウトと見た目の構成              |
| UI 基盤        | Radix UI 系コンポーネント | アクセシブルな基本 UI 構築            |
| アイコン       | lucide-react              | ステップ、操作、状態表示              |
| 永続化         | Cloudflare D1             | 認証データと比較メモ保存              |
| 配備           | OpenNext for Cloudflare   | 本番ビルドおよびデプロイ              |

## 4. システム構成

### 4.1 構成要素

- ホームページ
- 保存済みメモ一覧ページ
- 比較編集ページ
- メモ閲覧ページ
- 認証設定
- 画面全体制御コンポーネント
- ステップ表示コンポーネント
- 各ステップ UI コンポーネント
- 保存 API ルートハンドラ
- D1 アクセス層
- 型定義と定数
- 共通 UI コンポーネント群

### 4.2 構成イメージ

```text
page.tsx
  -> public memo list

/memos/page.tsx
  -> my memo list

/memos/new/page.tsx
  -> GadgetComparison
       -> StepIndicator
       -> CategoryStep
       -> PointsStep

       -> EvaluationStep

/memos/[memoId]/page.tsx
  -> ComparisonMemoView

auth.ts
  -> /api/auth/[...nextauth]

/api/memos
  -> comparison-memos.ts
  -> D1
```

## 5. レンダリング方針

- ホーム、保存済みメモ一覧、メモ閲覧ページはサーバー側でデータ取得と初期表示を行う。
- 比較編集ページはクライアントコンポーネントを中心に実装する。
- 全体状態は 1 箇所で保持し、各ステップへ props として受け渡す。
- ステップ切り替えは現在ステップ番号に応じて条件分岐描画する。
- 認証と保存済みメモ操作はサーバー側 Route Handler で処理する。

## 6. 責務分担

### 6.1 ページ層

- ページコンポーネントは route ごとのデータ取得と主要コンポーネント表示を担う。

### 6.2 オーケストレーション層

- 現在ステップ管理
- 比較データ全体の保持
- 進行可否判定
- 前後移動
- リセット処理
- 各ステップへのデータ受け渡し

### 6.3 表示層

- 進捗表示
- ステップごとのフォーム表示
- スコア入力 UI
- 集計結果 UI
- 最終選択 UI

### 6.4 型・定数層

- 比較データの構造定義
- 初期比較ポイント定義
- ステップ定義

## 7. 状態管理方針

- 画面全体状態は単一の ComparisonData と currentStep で管理する。
- 保存済みメモに関する状態は activeMemo、savedMemos、各種ダイアログ状態として管理する。
- 各ステップ固有の一時状態は必要に応じてローカル state を使う。
- 未保存データの自動永続化や URL 同期は行わない。

## 8. 画面実装上の表示方針

- ステップごとに主要な目的を明確にし、見出しと説明文を表示する。
- 重要状態は色、アイコン、数値で識別可能にする。
- モバイルとデスクトップで表示形式を切り替えるが、入力可能な情報量は同等に保つ。
- 画面表現の思想、配色、タイポグラフィ、情報密度、インタラクション原則は 10\_画面デザイン方針.md を参照する。

## 9. 外部依存

- 保存済みメモ機能では Google OAuth を利用する。
- 保存済みメモ機能では Cloudflare D1 を利用する。

## 10. 今回の設計上の特徴

- 小規模アプリに対して過度な状態管理ライブラリを導入せず、React の標準 state で完結している。
- 比較編集画面が単一ページ構成のため、利用者は比較フローを中断しにくい。
- 型定義を中心に、画面入力、評価、集計の整合性を保っている。
- ログイン必須を保存系操作のみに限定し、比較体験の入口を軽く保っている。
