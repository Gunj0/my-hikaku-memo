# コンポーネント責務設計

## 1. 文書の目的

本書は、主要コンポーネントの責務、入出力、依存関係、変更影響範囲を整理する。

## 2. 責務分割の方針

- ページ入口は最小責務とする。
- 比較フロー全体の状態管理は 1 コンポーネントに集約する。
- ステップ UI は表示と局所入力処理に集中させる。
- 共通 UI 部品は見た目と基本操作の提供に徹する。

## 3. 主要コンポーネント一覧

- Home page: 公開メモ一覧と主要導線を表示する。
- MemosPage: ログインユーザー向けの保存済みメモ一覧と公開プロフィール編集導線を表示する。
- NewMemoPage: 比較編集画面を表示する。
- MemoDetailPage: 公開メモまたは所有メモの閲覧画面を表示する。
- auth.ts: Google ログイン設定とセッション初期化を行う。
- GadgetComparison: 画面全体の状態管理とステップ制御を行う。
- StepIndicator: 進捗表示と到達済みステップ遷移を提供する。
- CategoryStep: カテゴリ選択とカテゴリメモ入力を提供する。
- PointsStep: 比較ポイント編集と重要度設定を提供する。
- ProductsStep: 候補製品登録と製品メモ入力を提供する。
- EvaluationStep: 評価点と評価メモ入力を提供する。
- SummaryStep: 集計結果の可視化を提供する。
- DecisionStep: 最終決定製品の選択と理由入力を提供する。

## 4. ページ入口

### 4.1 Home page

- 公開メモ一覧を取得して表示する。
- 公開メモの投稿者表示にはアプリ側プロフィール名と仮アイコンを使用する。
- 新規比較開始と保存済みメモ一覧への導線を提供する。

### 4.2 MemosPage

- ログイン中ユーザーの保存済みメモ一覧を表示する。
- ログイン中ユーザー向けのログアウト導線を表示する。
- ログイン中ユーザーの公開プロフィール名編集 UI を表示する。
- 未ログイン時はログイン前提の案内を表示する。

### 4.3 NewMemoPage

- 比較編集画面を表示する。
- グローバルヘッダーを表示しない。
- memoId クエリがある場合は、対象メモの再開導線を渡す。

### 4.4 MemoDetailPage

- 公開メモまたは所有メモの閲覧画面を表示する。
- 所有者だけに編集再開導線を表示する。

## 5. オーケストレーション層

### 5.1 GadgetComparison

#### GadgetComparison の責務

- 初期 state を構築する。
- 現在ステップを管理する。
- 比較データ全体を管理する。
- 保存済みメモ一覧、現在編集中メモ、各種ダイアログ状態を管理する。
- 保存済みメモ読込時に、入力状況に応じた再開ステップを決定する。
- ステップ進行可否を判定する。
- 前へ戻る、次へ進む、直接移動、リセットを制御する。
- 保存、読込、削除、ログイン案内の UI 導線を制御する。
- ステップごとに必要な props を受け渡す。

#### 持つべきでない責務

- 各ステップ固有の入力 UI の詳細制御
- 共通 UI パーツの描画ロジック

#### 変更影響

- ステップ追加や遷移条件変更時の主変更点になる。
- ComparisonData の構造変更が最も影響しやすい。

## 6. 進捗表示層

### 6.1 StepIndicator

#### StepIndicator の責務

- 現在ステップと完了済みステップを表示する。
- 到達済みステップへのクリック移動を提供する。
- モバイルとデスクトップで表示形式を切り替える。

#### 入力

- currentStep
- onStepClick

## 7. ステップ表示層

### 7.1 CategoryStep

- カテゴリ選択 UI を提供する。
- プリセットとカスタムカテゴリ入力を扱う。
- カテゴリメモ入力を扱う。

### 7.2 PointsStep

- 比較ポイント一覧の表示と編集を行う。
- ローカル state として新規入力値、展開状態、IME 状態を管理する。
- 重要フラグ、重要度、ドラッグアンドドロップによる表示順、メモを編集する。
- 初期値復元操作を提供する。

### 7.3 ProductsStep

- 候補製品一覧の表示と編集を行う。
- ローカル state として新規入力値、IME 状態を管理する。
- 候補追加、削除、ドラッグアンドドロップによる表示順変更、個別メモ編集を提供する。

### 7.4 EvaluationStep

- products と重視ポイントをもとに評価入力 UI を構築する。
- モバイルではカード形式、デスクトップでは表形式を提供する。
- score 更新、memo 更新、比較 UI 上での重視ポイントと候補のドラッグアンドドロップ並び替えを行う。

### 7.5 SummaryStep

- 重視ポイントと score から集計結果を算出する。
- 順位、合計点、達成率、内訳を表示する。
- 入力操作は持たない。

### 7.6 DecisionStep

- 集計順に候補を表示する。
- selectedProductId に基づく選択 UI を提供する。
- 決定理由入力を提供する。
- 選択解除操作を提供する。

## 8. 共通 UI 層

- Button、Input、Textarea、Checkbox、Table などの汎用 UI を提供する。
- 業務ロジックは持たない。
- ステップコンポーネントはこれらを組み合わせて画面を構成する。
- テーマトークンに従い、青紫系の操作色、success トークンによる成功色、薄いボーダー、小さめ角丸を一貫して提供する。
- ホバー速度とアニメーション長は共通 UI 側で制御し、各ステップで個別にばらつかせない。

## 8.1 認証・保存層

### auth.ts

- Auth.js と Google Provider の設定を保持する。
- D1 Adapter とセッション戦略を初期化する。
- Cloudflare 環境で trustHost を有効化する。
- 初回ログイン時にアプリ側の仮ユーザー名と仮アイコンを割り当てる。
- セッションコールバックで session.user.id とアプリ側プロフィールを付与する。

### /api/profile

- ログイン中ユーザーの公開プロフィール名更新を処理する。
- 未ログイン時は 401 を返す。
- 入力値を検証し、更新後プロフィールを返す。

### /api/memos

- ログイン中ユーザーの保存済みメモ一覧取得と新規保存を処理する。
- 保存時の公開設定を受け取り、永続化へ渡す。

### /api/memos/[memoId]

- 保存済みメモの読込、更新、削除を処理する。
- 読込、更新、削除はいずれもログイン済みユーザーを前提とする。
- 更新と削除は memoId と userId の組み合わせで対象を特定し、本人所有メモに限定する。
- 所有者以外には非公開メモを返さない。

### comparison-memos.ts

- D1 との永続化処理を集約する。
- 保存済みメモのスキーマ検証と CRUD を提供する。
- 所有メモ向け取得と公開メモ向け取得でフィルタ条件を分けて提供する。
- 公開メモ一覧と公開詳細のフィルタリングを提供する。
- 公開面で使用する投稿者プロフィール情報を整形する。

## 9. 依存関係の方向

```text
page
  -> flow controller
  -> auth/session provider
  -> memo api routes
       -> step components
            -> ui components

flow controller / step components
  -> types
memo api routes
  -> comparison-memos.ts
```

## 10. 保守上の観点

- 状態項目追加時は、まず ComparisonData と初期値構築を見直す。
- 進行条件変更時は GadgetComparison と関連要件文書を見直す。
- 集計ルール変更時は SummaryStep と DecisionStep の共通ロジック重複に注意する。
- ステップ画面の見た目変更は各 Step コンポーネント内で完結しやすい。
