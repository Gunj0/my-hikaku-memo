# 非機能要件定義

## 1. 文書の目的

本書は、現行アプリに求める品質特性、利用環境、制約、運用前提を定義する。

## 2. 対象環境

- 利用形態は Web ブラウザによる利用とする。
- PC とスマートフォンの双方からの利用を想定する。
- 日本語利用を前提とする。

## 3. ユーザビリティ要件

- 比較フローは 1 画面で完結し、利用者が現在位置を見失わないこと。
- 各ステップの主目的が見出しと補足文で把握できること。
- 次へ進めない場合はボタン無効化により状態が分かること。
- 重視ポイント、最高評価候補、選択済み製品など重要情報が視覚的に識別できること。

## 4. レスポンシブ要件

- モバイルでは横幅制約を前提とした表示に切り替えること。
- デスクトップでは比較しやすい表形式を優先すること。
- 進捗表示はモバイルで横スクロール可能とし、全ステップへのアクセス性を維持すること。

## 5. 性能要件

- 画面操作に対する応答は利用者が待機を意識しない範囲であること。
- ステップ移動、スコア入力、候補選択など主要操作はクライアント側で即時反映されること。
- 現行想定の少量データでは、サーバー往復なしで画面更新が完結すること。

## 6. 可用性・信頼性要件

- 比較フローの入力と集計はログイン有無にかかわらず利用できること。
- 保存済みメモ機能は Google OAuth と D1 に依存するが、これらが利用できない場合でも比較フロー自体は継続利用できること。
- 未保存データについてはブラウザ再読み込みや離脱時の保持を保証しないこと。

## 7. データ保持要件

- 未保存の入力データはブラウザ実行中のメモリ上に保持する。
- 利用者が明示的に保存した比較メモは D1 に永続保持する。
- 保存済みメモはログインユーザー単位で分離されること。
- 保存済みメモの既定公開状態は非公開であること。
- リセット操作により、画面上の編集中データは明示的に破棄されること。

## 8. セキュリティ要件

- 認証は Google OAuth を利用して行うこと。
- セッションは Auth.js のデータベースセッションで管理すること。
- 保存済みメモに対する取得、更新、削除は本人のアカウントに限定すること。
- 非公開メモは所有者以外から取得できないこと。
- 利用者入力は保存時と読込時にサーバー側で扱われるため、入力形式を検証すること。

## 9. アクセシビリティ要件

- ボタン、入力欄、チェックボックスなど基本操作要素には適切なラベルが付与されること。
- ステップ進行や選択状態は色だけに依存せず、文言やアイコンでも識別可能であること。
- キーボードで主要操作が行えることを考慮すること。

## 10. 保守性要件

- 画面全体の状態管理、ステップ UI、共通 UI を分離し、変更影響を限定できる構成であること。
- データ構造は型定義として集約し、仕様変更時に影響点を追跡しやすいこと。
- スコア集計ロジックは画面表示から読み取れる形で明確であること。

## 11. 運用・配備要件

- 開発時は Next.js 開発サーバーで動作すること。
- E2E 自動テストは Playwright を利用し、現行の実行対象ブラウザは Chromium のみとすること。
- 本番配備は OpenNext を用いた Cloudflare 環境を前提とすること。
- Cloudflare 側に Google OAuth 用 secret と D1 binding を設定すること。
- 環境定義変更時には Cloudflare 型定義の再生成が必要であること。

## 12. 技術制約

- フロントエンドは Next.js と React を前提とする。
- UI 実装は既存の共通 UI コンポーネント群を利用する。
- 認証は Auth.js を前提とする。
- 永続化は Cloudflare D1 を前提とする。
- サーバー側の保存処理は App Router の Route Handler で実装する。
